## Исправление по новому правилу пользователя

Статус: SOURCE FIX; DLL не собиралась/не устанавливалась, gameplay OPEN.
Первоначальный анализ ниже исторический по состоянию исходников.

Пользователь: все возрождаются на последней лампе, зажжённой любым игроком;
дополнительно ограничить соседние карты. Предыдущее правило личной лампы
для независимого режима заменено общей точкой группы.

- Локальный7100/12907010 после штатной анимации публикует факт зажигания.
  Хост упорядочивает активации и рассылает последнюю точку всем, независимо
  от их карты и роли. Повторное зажигание выбирает лампу и при совпадающем
  личном checkpoint. Shared unlock masks/snapshots и обычные поездки не
  считаются зажиганием и не переставляют общую точку.
- ControlKind::LampCheckpoint=13 в существующем control channel, точка+sсope,
  host revision, origin/sequence и retry/ack. Старые предложения не откатывают
  выбор, запоздалый ack может закрыть retry без применения старого checkpoint.
  Хост повторяет canonical для позднего подключения. Начальная точка группы
  однократно берётся из имеющегося checkpoint хоста; история активаций до
  создания группы не восстанавливается. Одновременные активации упорядочивает
  координатор по приёму, без сравнения часов разных машин.
- ResolveLastLampTransform отклоняет любую другую текущую карту ДО native
  point lookup, даже если сосед resident. Для чаш требуется тот же key+ritual
  и готовая загрузка. Ограничение действует также на личный fallback до
  получения общей точки. Первоначальный shared-first приоритет оказался
  регрессией для победы над боссом и отменён, см. актуальный раздел выше.
- Для полной загрузки фиксируется цель текущей смерти, подготавливаются её
  scope/snapshot/mount, затем original013CDF30(point EDI) выбирает карту и
  точку и вызывает StageTransition. Используются существующие phase3 guard,
  FirstSync и bootstrap, без анимации поездки и без координатного переноса
  между картами. Новое зажигание во время загрузки относится к следующей смерти.
  Snatcher сохраняет свой отдельный native prison load. При исчезнувшей чаше
  или недоступности данных30с остаётся штатный local death reload; удалённую
  чашу не подменяем другой чашей с теми же m29 point IDs.
