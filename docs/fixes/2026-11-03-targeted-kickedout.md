# Адресный KICKEDOUT: отключение и уведомления

Исходный прогон: 03.11.2026, 00:44–00:59 МСК, сбор
`bloodborne_pc/out/coop-dev/runs/review-20261103-0100`. Хост P1/test1;
исключает P3/user3 в 00:56:34.755, P2/user2 в 00:57:20.504.
VPS исполняет kick в 00:56:36.461 / 00:57:22.508, но начало возврата
клиентов задерживается до 00:56:57.754 / 00:57:57.924. Перед этим оба
достигают native bound1001 и вызывают Stop с 0x1789812. См. уточнение
в `2026-11-03-session-review-0100.md`. Эти два разрыва — после адресного
исключения, а не доказанные самопроизвольные обрывы.

## Установленная причина

shadNet посылает исключённому участнику RoomEvent 0x1103 с cause=2,
error_code=0xFF000019; оставшимся — MEMBER_LEFT. Клиент строил
OrbisNpMatching2RoomUpdate с eventCause/errorCode и нулевой optData.

Native eboot 1.09 проверяет optData.len == 4 по смещению +0x18:
CC3E80 (обычная обработка) и CC4209 (вторая ветка), затем читает причину
из optData.data по +8. При len=0 обе ветки молча выходят. При правильной
причине вызывается C98070 и ставится native событие типа 0x1E, которое
в обработчике 0178B5E0 приводит к OnBeKickOut (строка при 0178C0C3).
Один errorCode по +4 этого не заменяет. Это воспроизводимый дефект
преобразования SDK payload, соответствующий задержке в прогоне.

Прочитан original global_event.lua из eventcommon.luabnd.dcx, без изменений
игровых файлов. OnBeKickOut сначала проверяет 4047, выводит информацию,
ставит OnLeave_Limit через 5 секунд, поднимает 4047 и SetLoadWait.
Штатный пятисекундный отсчёт сохранён; ожидание переполнения native
очереди для срабатывания исключения больше не требуется.

## Исправление клиента

BBGL `BuildKickedOutUpdate` переносит известную BBSC-причину FF000019
при KICKOUT_ACTION в четыре байта optData, сохраняя прочие поля.
Другие причины/ошибки не переинтерпретируются. Событие старой комнаты
отбрасывается до доставки; target контекст и ownership callback payload
сохранены. Параметры комнаты/лимиты очередей/пакеты не меняются.
Добавлена INFO-запись KICKEDOUT с ctx/room/cause/status/presence length.
Серверный код и wire protocol не изменены, обновление VPS не требуется.

BBSC обрабатывает именно OnBeKickOut, а не broadcast OnLeavePlayer:
при собственном исключении гостя отключает удержание сессии, освобождает
оставшиеся leave locks до Lua-проверки 4047 и показывает «Хост отключил
вас. Возвращение в свой мир». Повторное событие не дублирует уведомление;
новый native JoinSession сбрасывает отметку. Активная загрузка или уже
заявленный возврат не разблокируются повторно. Хост и собственный мир
не проходят эту политику.

Хост получает «Отключение выбранного игрока...» в точке реального
native запроса исключения выбранного кооператора (вызов 0178DBE0 из
015BE45D). Это сообщение о запросе, не ложное подтверждение серверного
результата. Проверяется роль хоста, точный вызывающий адрес и валидный
member id выбранного удалённого персонажа. Отмена выбора, другой native
caller, локальный игрок и действия гостя не создают это уведомление.
Оставшийся гость сохраняет прежнюю защиту от чужого send-home.

Новые тексты EN/RU идут через существующий co-op banner и два явно
разрешённых notice type. Обычные native leave messages не отключаются.
Служебные suppressed draws длиной 13 из прежнего прогона сами по себе
не доказывали скрытие kick-уведомления; исправление не основано на таком
предположении. Точное визуальное поведение новой сборки ещё не проверено.
