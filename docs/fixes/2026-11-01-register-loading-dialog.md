## Исправление ошибочного guard — 01.11, после прогона 23:21

Предыдущее объяснение `owner+0x2858` как номера доски ниже ОШИБОЧНО.
Это zero-based first rank: native 1B3181C/1B333F4 записывает 0,
1B332D0/scroll handlers меняют смещение; 1C93000 передаёт его в
14A1910, где 14A19D8 прибавляет 1 для первого ранга запроса.
Guard `==19` блокировал правку при обычном открытии книги (`==0`).
Fixture сам задавал 19, поэтому подтвердил ошибочное предположение.

Bundled 9d992e8 / standalone 63b789f: guard проверяет первую страницу
(`==0`); scope обеспечивается актуальным поколением BookUse и результатом
именно нашего board20 Range(first=1). Другие страницы не используют
число строк первой страницы. Native готовность реальных строк сохраняется.
Добавлена ограниченная запись фактического завершения native ожидания.

Fixture теперь исполняет реальные байты native initializer +2858=0,
затем настоящий predicate через production trampoline. Проверки ready/pending,
1/2/5 rows (пользовательский случай 1 покрыт логикой expected), пустого хвоста,
пустого ответа, прошлого открытия и другой страницы проходят.
test_session_register.py PASS. Игровое подтверждение всё ещё требуется.

## Нативный путь

SP_ダイアログ.fmg, ID 305003 — искомый текст (0x4A76B).
В 0x01B322C0 запускается читатель таблицы (0x01C93000), затем создаётся
ожидание 0x01C1F7C0 с callback-vtable 0x0533A5C0.
Его predicate +0x10 = 0x01B33190 читает owner из [functor+8],
число слотов [owner+0x1120] и требует ненулевого первого байта КАЖДОГО
элемента размером 0x50 начиная с align8(owner+0xDF8).
Читатель запрашивает до 10 записей. В сессии мода реально от 0 до 5 строк;
пустые хвостовые места могут остаться неготовыми и удерживать ожидание.
Этот случай воспроизведён на оригинальных машинных инструкциях predicate.
Фактическое содержимое UI-cache в пользовательском прогоне не снималось.

Board в owner+0x2858 имеет нулевой индекс 19: 0x014A1910 прибавляет 1,
получая наш NP Score board 20. Критерий ограничен именно этой доской.

## Исправление

При создании Ranking начинается новое поколение загрузки. Успешный локальный
Range(first=1), включая завершённый пустой результат, публикует поколение
и фактическое число переданных строк. Запросы с ошибкой параметров не публикуют
готовность; данные предыдущего открытия её не подтверждают.

В entry 0x01B33190 установлен byte-checked hook: MOV RAX,[RDI+8] и
LEA RCX,[RAX+DF8], суммарно 11 байт без RIP-addressing/внешних переходов.
После получения актуального ответа он проверяет готовность именно реальных
строк в нативном UI-cache. Если все готовы — возвращает true из штатного
predicate. Пустые хвостовые слоты больше не удерживают диалог.

Готовность до заполнения реальных строк не подделывается. Чужие доски,
неполученный/старый ответ, невалидные границы и выключенный провайдер идут
в оригинальный predicate. Память строк, флаги нативных задач и ownership
не меняются; закрытие/анимацию/освобождение ожидания выполняет сама игра.
Второй диалог загрузки карточки персонажа (native 25-секундный fallback)
этим изменением не затронут; карточка экипировки не входит в текущую книгу.
