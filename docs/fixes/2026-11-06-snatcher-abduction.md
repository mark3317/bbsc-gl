# Личное похищение в тюрьму Яаар'гула

Статус: исправлены исходники, целевые проверки PASS. DLL не собрана и не
установлена; игровой результат OPEN. Пользователь уточнил: переносится только
погибший, один раз для каждого персонажа, а не вся группа.

Оригинальные CUSA03173 1.09 EMEVD прочитаны из установленной игры, без изменений:

- `12400780` (m24_00) и `12700500` (m27_00) проверяют тип местного охотника,
  последнего атакующего, смертельное HP и исходные сюжетные условия; ставят 9420.
- common `9421` завершён после 9423, иначе отсекает клиента; ждёт 9420,
  выбирает точку 2802959, сбрасывает 9420. Само завершение события ставит 9421.
- common `9422` также отсекает клиента; после 9421 и прибытия в m28_00
  запускает катсцену 28000010, ставит 9423 и даёт штатный эффект 4680.

Изменения:

- Все четыре события локальны. Только у 9421/9422 проверенный EndIfClient
  в загруженной памяти заменён штатным WaitFrames(0); остальные условия,
  параметры врага, команды, катсцена и награда сохранены. Проверка type0
  в детекторах разрешает гостю выполнить собственное оригинальное событие.
- 9420..9423 включены в существующую защиту личных флагов, сохранение native
  completion и личный журнал. Чужой снимок не выдаёт и не сбрасывает этот
  прогресс; штатный результат сохраняется в личном мире. Нового файла квитанций,
  опроса врагов или искусственного определения убийцы нет.
- Кооперативная смерть, включая позднее появление 9420 после death step,
  ждёт завершения 9421 и точки 2802959, затем запрашивает оригинальную death
  load. Возрождение у фонаря и spectator fallback этот переход не перехватывают.
- 9421/9422 не ждут инициализации сетевых врагов; исходные детекторы врагов
  сохраняют обычный bootstrap barrier. Обе схемы native channel31 отфильтровывают
  чужие продолжения личной цепочки, включая timed continuation.
- Катсцена 28000010 не рассылается партнёрам и не воспроизводится из чужого
  cutscene packet. Собственное штатное воспроизведение сохраняется.

Проверки (синтетическая память/таблицы, настоящие сейвы не менялись):

- `test_snatcher_abduction.py`: реальные production predicates/EndIfClient
  rewrite, правильное ожидание точки, завершённое похищение, feature-off,
  чужие события/недоступная запись. Read-only audit исходных EMEVD PASS.
  Negative control без разрешения гостевых событий ожидаемо FAIL.
- `test_independent_death_destination.py`: production spectate controller,
  обе роли, партнёр жив, задержанный выбор тюрьмы, уже запрошенная death load,
  отсутствие повторной загрузки; обычные смерти/лампы сохраняют свои проверки.
- `test_native_pickup_state.py`: реальные protection/native-completion/journal
  функции для всех четырёх флагов, входящий чужой прогресс в обе стороны,
  сохранение и сброс собственных результатов. Только искусственные таблицы.
- `test_scripted_pickups.py`: production type0 hook для обоих детекторов,
  localization всех четырёх событий до любого шага; прямые зависимости PASS.
- `test_world_native_bootstrap.py`: 9421/9422 проходят при закрытом world barrier,
  сетевые world events продолжают ждать, joining не обходится.
- `test_personal_event_transport.py ../../out/exit-study.elf`: полные исходные
  native senders/receiver и реальные Windows trampolines, оба типа channel31,
  обе роли и все четыре события, включая выключенный NPC switch, PASS.
- Полный MOD/relay syntax exit0, `build/snatcher-syntax.log` (предупреждения CRT).

HEAD/pin 4989896 без изменения. В дереве много ранее существовавших правок:
смешанный коммит не создан. Игра PID26236 продолжает работать; DLL не заменялась.
Нет изменений реальных сейвов, настроек или файлов игры, завершения процессов,
push либо публикации.

Игровой контроль после общей сборки: сначала Похититель убивает гостя —
катсцена и тюрьма только у гостя; затем впервые убивает хоста — только у хоста.
Повторная смерть каждого от него не повторяет похищение; обычная смерть и
партнёр в другой локации не вызывают перенос. Проверить сохранение личного
результата после выхода/повторного входа в кооператив.
