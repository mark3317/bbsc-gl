# Снижение пиков BBSC без пропуска игровых проверок — 06.11.2026

Основание: родительский docs/fixes/2026-11-06-bbsc-perf-results.md.
Пики TickBbscMessages84/56мс, NpcPass около2мс/тик, личные флаги около2проходов/тик.

## Изменения

1. `BbscEventIdOf` больше не перебирает целиком EMEVD directory на каждый
   запрос из guards и условий. Он использует тот же проверяемый индекс диапазонов,
   что и локализация. Общий resolver проверяет живые instance/ref/file/header/row,
   адреса/число строк и PC; кеширует идентичность, а не права памяти. Карты кешей
   thread_local, native reload повышает общий epoch и инвалидирует каждый поток.
   Смена ID/строки по прежнему адресу приводит к перестроению; пересечения сохраняют
   приоритет первой строки оригинального directory даже при движении PC.
   Негативный поиск не сканирует всю таблицу повторно.
2. Локализация не пишет0 в network-sync byte, когда там уже0. При native reset
   значения1 следующий шаг по-прежнему устанавливает0. Все guards bootstrap/travel,
   личных квестов, подбора и похищения остаются на своих границах.
3. `TickBbscMessages` получает текущий контекст категории FMG один раз за проход,
   переиспользует найденную строку/offset только при совпадении live repo, version,
   categories, FMG, tables, count, load generation и row header. Каждый используемый
   слот проверяется заново. Повторного полного поиска по группам для неизменённых
   строк нет. Неизменённые тики не выполняют запросы памяти. Оставлена лёгкая
   проверка раз в2с: native может заменить значение слота без смены репозитория.
   Подтверждено восстановление таких замен, смена языка, поздняя загрузка категории,
   переиспользование строки/таблицы/адреса и повтор после отказа доступа.
   Строки переводов и подстановки не менялись.
4. Проход личных NPC-флагов не делает отдельный ReadValue/VirtualQuery для каждого
   бита: живой125байтный span группы проверяется перед её флагами в каждом проходе,
   затем читаются нужные байты. Адреса/права не сохраняются между проходами.
   Оба прохода (tick и перед event/talk) сохранены: между ними возможна новая
   сетевая запись. Native receipts/completions и защита чужих квестовых битов
   сохраняют прежнюю семантику.
