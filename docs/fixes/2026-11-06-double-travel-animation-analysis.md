# Двойная анимация перед поездкой в пустую локацию

## Исправление исходников — 06.11.2026

Исторический анализ ниже сохраняет границы старых логов. По новой просьбе
пользователя runtime исправлен: убран отдельный ForceAnimation013CBFD0 из
принятия команды и убрано пропускание целой2004[14] в BbscBellRefundHook.
Единственный владелец анимации теперь оригинальное событие7200/12107000/
12107100/12907020. Второй этап алтаря12107200 по-прежнему не анимирует.

Точный дефект прежнего решения в исходниках: оно создавало две раздельные
цепочки запуска и заменяло native команду анимации простым return1. Это
не эквивалентно штатному действию. Original bank2004[14] вызывает013E0D80,
а ранняя ветка013CBFD0 — другой helper. 013E0D80 не только пишет animation
request, но создаёт native controller task и ставит chr+58/+111; старое
подавление отбрасывало весь этот путь. Независимой блокировки action buttons
на время поездки не было. Busy в Queue защищал только повторный travel flag.
Новая реализация устраняет две цепочки, вместо дальнейшего угадывания условий
подавления. Какая именно ветка старого suppression не сработала в записанном
эпизоде, старые логи всё ещё не доказывают; это не выдаётся за установленный факт.

С принятия итоговой команды поездки native action registration01CD91F0
возвращает false на ВХОДЕ, до регистрации/побочных эффектов: лампы, NPC,
предметы, двери, рычаги. Штатный accepted-action observer01CD97E6 не меняется.
Gate привязан к world/load; живёт во время queued/inflight, включая позднее
назначение и начало native load. При прибытии, отмене, смерти, выходе из сессии
или смене мира/загрузки gate прекращает действовать. Первый этап алтаря сам
по себе ещё не поездка: его меню выбора слоя/отмена работают как раньше;
после принятия слоя взаимодействия закрыты. Новая установка hook обязательна
для открытия independent travel; ошибка не оставляет открытый незащищённый путь.

Изменение поведения: отдельной немедленной анимации больше нет. Если original
condition задерживается, анимация начнётся вместе со штатной фазой, а кнопки
взаимодействия всё это время закрыты. Дополнительное ожидание condition3[0]
этой правкой не сокращено и его внутренний native predicate не установлен.

## Вывод и границы

Подтверждён разрыв раннего запроса анимации и продвижения original события:
при пустом назначении в этих эпизодах около5.3–5.6с дополнительного ожидания,
при занятом около0–0.03с, затем штатные4с до stage. Ранний ForceAnimation
в RequestBbscTravelAnimation запускает только анимацию; он не переводит
оригинальное событие через условие и не вводит общий запрет взаимодействий.
QueueBbscWorldTravel отклоняет повторную поездку как busy, но это не запрет
вновь открыть устройство или взаимодействовать с другими объектами.

Механизм согласуется с пользовательским наблюдением: ранняя анимация успевает
закончиться до штатной фазы. Но текущие логи НЕ записывают результат
BbscWorldTravelAnimationHandled, фактические args позднего bank callback и
реально исполненные запросы контроллера анимации. Поэтому нельзя считать
доказанными ни конкретную ветку обхода подавления повтора, ни внутреннюю
причину позднего продвижения condition3[0]. Само отсутствие другого игрока
в назначении здесь коррелирует с задержкой; конкретный native predicate
требует отдельного подтверждения. Объявлять root cause полностью установленной
или баг исправленным по этим логам нельзя.

Следующий целевой шаг: ограниченная диагностика выбранного instance12107000,
результата/причины animation suppression и обоих native animation helpers,
а также фактического выполнения condition3[0]. Нужен единый жизненный цикл
анимации/взаимодействий поездки, согласованный со штатной цепочкой.

Сейвы, settings, оригинальные игровые файлы не менялись; тесты не запускались,
так как runtime не изменялся. Процессы не завершались; commit/pin/push нет.
