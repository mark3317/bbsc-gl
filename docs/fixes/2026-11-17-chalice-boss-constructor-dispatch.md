# 17.11.2026 — потерянные конструкторы босса чаши

## Доказанная причина

В запущенной 01e6ca3 read-only снимок PID42284 и PID8940 показал полностью
нулевой bbsc_chalice_boss_attempts (scope/load/vector), пустой набор
bbsc_boss_wipe_attempt.flags и reset=true. При этом wipe_scope совпадает с
bootstrap_scope (ритуал10), wipe_load совпадает с native_load. Следовательно,
сброс проходил проверку загрузки, но выходил по пустому списку флагов.
Глобальные адреса определены по COFF текущей сборки и двум RIP-relative
деструкторам DLL; проверены независимыми scope/load значениями.
Скрипт только OpenProcess/ReadProcessMemory, без записи игровой памяти:
BBGL work/boss-wipe/read_globals.py.

RememberBbscChaliceBossInit вызывался из entry 012ECDC0 только на текущем PC.
Оригинальный ELF: после dispatch 017B93A0 и iterator 012EF2E0 ветка 012ECF9A
возвращается на 012ECE10, не через entry hook. Команды InitializeEvent в середине
конструктора 0 выполнялись без наблюдения. Старый fixture напрямую вызывал
Remember для каждого конструктора и поэтому не воспроизводил пропуск.

## Исправление

Наблюдение перенесено на штатный bank2000 dispatcher 017C8030 (instance RSI),
только opcode0 и event0. Нативный код продолжает исполняться без изменения.
Аргументы берутся из instance+B8, когда игра уже разрешила подстановки,
иначе из проверенного EMEVD. Нет нового опроса, таймера, повторного прохода
событий или сканирования памяти. Дополнительный callback вызывается на
командах bank2000; неподходящие команды сразу возвращаются. Старый вызов
на каждом обновлении event0 удалён. Отдельная точка dispatch необходима,
поскольку entry hook принципиально не видит внутренние команды.

Существующие Mark/Reset/Keep теперь получают заполненный набор арены.
Добавлены сообщения boss wipe prepared и boss wipe reset skipped, чтобы
пустой набор больше не скрывался за отсутствием сообщения.

## Проверка

PASS tools/test_boss_wipe_flags.py с оригинальными EMEVD и SetFlag из ELF.
Добавлены исходные байты внутренней петли/новой точки, вызов настоящего
bank callback, реальные конструкторы m29_10_90_00 и слой2 Watchers:
12905511/12/13, 12906795, 12906803; победа12901801, доступ12900536 сохранены.
Проверены старые снимки, флаги других слоёв, новая попытка, чужой ритуал,
resolved operands и отказ для другого события/команды. Существующие проверки
сюжета/DLC и остальных чаш также прошли. DLL не собиралась, установка и
игровое подтверждение этой правки не выполнены.

## Дополнительный запрос: гость входит первым

Отдельная недоработка, исследована, поведение не менялось.
PrepareBbscBossFogEvent снимает у 12906802 ожидание начала боя, подставляя
intro/access predicate. Но после успешного прохода шаг19 пишет только флаг
гостевого входа (в этом конструкторе12905512). Начало12905511 выставляет
host-fog12906796, тогда как setup12906795 ожидает начало перед включением ИИ
и полосок. Разрешение пройти само по себе не запускает бой. Исправление
должно связать успешный штатный проход с общим началом и учесть автора
снимка; простая локальная запись гостем может быть затёрта снимком владельца.
Никаких обходов барьера, принудительного ИИ или смены владельца не добавлено.
