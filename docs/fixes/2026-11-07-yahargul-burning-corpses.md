## Исходная диагностика (до исправления)

Read-only разбор оригинального m28_00_00_00.emevd.dcx и MSB основной установки:

- Constructor запускает12805920 в слотах0..3 для объектов2801600..2801603,
  model o281110. Флаги исчерпания:12805942/47/52/57.
- Если флаг исчерпания включён, событие удаляет object SFX и завершается.
- Иначе1003[1](skip1,ON,type2,id0) пропускает следующий CreateObjectSFX,
  если уже выполнен текущий слот события. Создание:2006[4](object,100,928020).
- Далее native2003[5] создаёт воздействие6032, исходное ожидание2секунды,
  restart. Значит, SFX создаётся только на первом проходе, воздействие повторяется.
- type2 означает EventIDAndSlotNumber (Bloodborne EMEDF for DarkScript3).
- В native017C64E0 ->013D9740 у2006[4] нет явного host/client запрета;
  helper ищет локальный объект013C99E0 и добавляет локальную запись SFX.
- BbscWorldApplyFlags переносит состояние карты до событий;12805920
  не выделен в персональные события/transport isolation.

Конкретный кандидат: клиент получает completed-slot12805920..23 раньше
своего первого создания928020. Он пропускает визуальную инициализацию,
но продолжает native воздействие. Особенно ожидаемо при позднем входе
или повторной загрузке карты. Для окончательного доказательства нужны
runtime slot flags/PC события и наличие локального object SFX в момент дефекта;
живые процессы/сейвы в этом разборе не читались и не менялись.

при сохранении общего исчерпания и native воздействия. Нельзя просто
