Пользователь подтвердил падение в пустоту и невозможность использовать предметы.

- 10:03:36.238 аварийный возврат использует forced map 0x1d000000, point -1, kept. Сообщения о восстановлении собственной точки нет за весь прогон. 10:03:41.459 home load completed, state 0 / own world; это завершение загрузки не доказывает пригодность мира.

Причина в production-коде: KeepBbscHomeSpot вызывается только WriteLuaSessionEvent (bloodborne_re.cpp:3505); функция вызывается из диагностического switch (21327), после ранних выходов при выключенном research/capture (20775, 20845). В обычном запуске capture пуст и записи return home: kept our spot отсутствуют. Поэтому PutBbscHomeSpot (10384) не может подменить адрес, который RequestBbscSessionWarp уже заменил картой/координатами хоста. GuardBbscStrayForcedWarp (10408) оставляет forced warp включённым, даже если PutBbscHomeSpot вернул false. TickBbscStrandedGuest (10908) идёт по этой ветке. Для чаши дополнительно требуется контекст конкретного подземелья; возврат в общий m29 после окончания гостевой сессии не является безопасным домашним возвратом. TickBbscChaliceBorrow сбрасывает borrowed context в собственном мире (5387).

Это конкретный дефект жизненного цикла домашней точки, согласующийся с логом и падением в пустоту. Не связано с неочищенным серверным claim: он успешно удалён. Точный итоговый набор геометрии/коллизий после загрузки не снят; падение подтверждено пользователем.

Дополнительно при этом home load перенесены 24 boss flags и 615 world flags (10:03:40.933), затем журнал подтверждает merge. Их допустимость нужно сверить с принятой политикой общего прогресса; отдельная причинная связь с падением не доказана, не объявлять повреждение файла сейва установленным.

Исправление должно вынести функциональные события JoinSession из диагностического writer в всегда работающий обработчик, сохранять точку до гостевой загрузки и предусмотреть безопасный собственный respawn при отсутствии снимка.
