# 17.11.2026 — первый вход гостя запускает бой

Исходная причина: гостевой проход разрешён до начала боя, но оригинальный
хвост пишет лишь entered (например, 12905512). Настройка Watchers12906795
ждёт battle-start12905511, который раньше выставлял только host fog.

В существующем bank2003 hook отслеживается только штатная запись entered=1
после успешного завершения прохода. Проверены оригинальные 23 события
сюжета/DLC/чаш: timeout/cancel ветка1000[7/107] обходит эту команду.
Ром с отдельным прыжком и без этой записи не подменяется.

Флаг начала передаётся существующему SetFlag. Штатные события сами включают
ИИ, HP-gauge и свою последующую логику; прямых записей AI/HP нет. В чашах
ID берутся из захваченного конструктора именно текущего ритуала и слота;
сюжет/DLC ограничены GuestFogGates и StoryArenas. Побеждённые боссы исключены.

Почему нужна передача события: native guest fog отключает network sync,
а снимки мира публикует владелец. Только локальная запись гостя не запустит
owner-side setup и может быть затёрта старым снимком. Добавлен BossEntrance14
в существующий WorldControl транспорт. Это однократная отправка при проходе,
не новый канал/очередь/опрос/повтор. Для каждого текущего резидента (до4)
отдельная запись108 байт с адресатом и обоими visit. Получатель сверяет
комнату/карту/ритуал, sender membership, оба visit, native loading boundaries,
разрешённую пару start/victory. Чужие, повторные и запоздавшие акты не оживляют
старую попытку. Доставка идёт через существующий SendBbscWorldFlagsToPeers.

На этой жизни локальные start (и entered у самого входящего) защищены от
старого общего/нативного/специального Dream снимка. Сохраняется текущее локальное
значение, а не принудительная единица. Следующая native load лишает эту защиту
силы; действует обычный boss-wipe reset. Точки контроля автора NPC и сессии
не менялись. Игра с новым протоколом проверяется на одинаковых сборках.
