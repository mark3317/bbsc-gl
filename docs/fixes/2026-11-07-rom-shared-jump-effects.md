## Цепочка

Read-only оригинальный m32_00_00_00.emevd.dcx из основной установки:

-13204820: type0 для10000 + область3202800 → ожидание →2004[15]

-13204821: исходный локальный аналог, с теми же защитой/SFX/5секундами;
  мод снимает только ожидание13204800 у гостя, сохраняя область.

Текущий GuestAccess::EventAllowed разрешает13204820. Production
BbscDreamTypeCheckHook поэтому пропускает его type0 и для session6.
Утверждение старого отчёта06.11 «host13204820 гостю не допускается»
больше не соответствует текущему коду. test_guest_access.py подтверждает
именно нынешний допуск; это не тест требуемой границы авторитета.

BbscIsolatedNativeEvent содержит13204821/32/33, но не13204820.
EventSteps::Classify/EnableBbscRomJumpEvent также не локализуют13204820.
Значит, host-event может стартовать у любого участника и отправить
condition progress/timed continuation остальным. В native scheduler
чужой progress способен освободить локально ложное ожидание. После него
каждая копия исполняет команды для своего10000. Это конкретный путь
массового повтора защиты и SFX; фильтрация локального13204821 его не закрывает.
Отдельная широковещательная команда SFX для объяснения не требуется.
