## Вывод

Существующая архитектура допускает случайное подземелье, выбранное игрой хоста,
с временной загрузкой той же раскладки у гостей. Подтверждённой готовности
корневых чаш в текущем Party нет. Отдельного отключения генератора или
принудительного seed в исследованных участках DLL/Party не обнаружено;
это не проверка исполнения оригинального генератора игры.

Обнаружен конкретный пробел текущего запуска: `party/compat.py::http_call`
не реализует `/channel/*`. Upload, search, word_search, get_info,
get_details_info и share возвращают общий `UnknownResponse`, пустые списки
и не возвращают ChannelId. Это воспроизведено вызовом реального метода
на минимальном объекте без запуска серверов, игры и обращения к профилям.
Уже сохранённая чаша с валидным контекстом может проходить другой путь;
пустой API не доказывает отказ каждого существующего подземелья.

## Что уже есть

- `core/bbsc_chalice.h`: ключ ChannelId + хеш/размер/версия FormData;
  Mount передаёт layout, 18 частей, тип, feature, stage map и revision.
- `bloodborne_re.cpp::BbscChaliceContextHook`: у хоста захватывает вход
  нативного загрузчика; у гостя подставляет согласованный контекст хоста.
  Проверки принадлежности к десяти фиксированным чашам здесь нет.
- `TickBbscFollowHost` / `PrepareBbscChaliceLoad`: загрузка вслед за хостом,
  включая смену контекста при одинаковой карте.
- `GateBbscChaliceSummon`: отдельная подготовка прямого входа к хосту,
  уже находящемуся в чаше; ожидание согласованных mount/follow/world flags.
- Borrowed context и защита записей флагов алтарей сохраняют личные алтари
  гостя; флаги и личный лут отделяются по идентичности подземелья.

Это основание для реализации, а не доказательство полноты параметров
корневых чаш, дополнительных обрядов и переходов всех слоёв.

## Старый сервер и текущий Party

В `server/gameserver/bbsc_gameserver.py` есть upload с сохранением переданного
FormData и выдачей ChannelId/глифа, share, info/details и поиск по глифу.
Его search обслуживает десять `FIXED_CHALICES`; остальные поиски намеренно
пустые. Это не код генерации произвольной геометрии. Десять фиксированных
описаний не доказывают подмену ими корневых чаш.

Основной Party использует собственный Compatibility; старый сервер не
запускается и не импортируется. Исторические записи об имеющемся channel API
не описывают возможности текущего Party.

## Необходимая доработка

1. Проследить оригинальный путь ритуала корневой чаши: создание FormData,
   запросы search/upload и повторное открытие. Установить, какие данные
   создаёт игра локально, а какие ожидает от сервиса. Не заменять это
   произвольным генератором seed или чужим результатом поиска.
2. Реализовать необходимые channel API в Party с постоянным каталогом
   описаний и устойчивыми идентификаторами. Хранилище не привязывать к
   эфемерной группе: чаша должна оставаться доступной после перезапуска.
   Не объявлять неизвестные старые ChannelId удалёнными.
3. Проверить полноту Mount для корневых чаш и всех обрядов. При необходимости
   расширить контекст/версию протокола; сохранить авторитет хоста,
   согласование revision и защиту от старых пакетов.
4. Проверить отдельную идентичность нового ритуала и точного слоя:
   текущая revision живёт в процессе и не является постоянным ID ритуала.
   Не снимать общее исключение m29 из Shared Progress.

Гостю для следования не требуется постоянная установка чаши на свой алтарь.
Общий поиск по глифам между компьютерами потребует отдельного обмена
каталогом; для уже передаваемого runtime-контекста хоста такой каталог у
гостя сам по себе не является обязательным условием.

## Подтверждение реализации

Сначала целевые проверки channel API, двух разных FormData при одинаковой
карте, смены ритуала/revision, отложенного прямого входа и устаревших пакетов.
Затем игровой маршрут: создать корневую чашу на хосте → следование из Сна →
позднее подключение прямо внутрь → рычаг/босс/следующий слой → смерть/вайп →
Сон/повторный вход. Отдельно проверить обряды, третьего игрока и сохранение
личных алтарей гостя. Memory fixtures не подтверждают загрузку игровых ресурсов.

В этом исследовании код продукта, сборка, установка, сейвы, настройки и
файлы игры не менялись; изменена только документация. Игровая поддержка
случайных чаш остаётся OPEN.
