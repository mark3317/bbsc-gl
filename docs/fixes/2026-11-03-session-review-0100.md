## Исправление установленного дефекта

Несмотря на прошлое исправление лаунчера, фактические UDP порты снова зависят
от порядка запуска: P3=3658, P2=3659, P1=3660. `bbnet_register` не вызывал
shadPS4 InstallKernelIntegration и не устанавливал `SystemHooks.p2p_port`.
`PortToBind` поэтому выбирал state.configured_port=3658; GetP2PPort с
BB_P2P_PORT вообще не вызывался. Исправление только Python этого не устраняло.

BBGL теперь устанавливает port/online settings hooks до регистрации сетевых
импортов; остальные ранее заданные hooks сохраняются. Явный порт, 0 для
автовыбора и стандартный fallback остаются. THD проходит своим прежним путём.
Это исправляет игнорирование настройки порта; связь этого дефекта с native
очередями и устранение разрывов игровым прогоном ещё не подтверждены.

BBSC в обоих деревьях наблюдает 0x1789742 сразу после отказа native send:
неизменённые target pointer, message kind и bytes из native frame. Не более
одной записи в 5 с / 128 за процесс. Хук не повторяет отправку, не удаляет
пакеты и не меняет native лимит. Отказ логического канала возможен ещё до UDP,
поэтому запись явно не называет его таймаутом ACK. Диагностика — не исправление
причины переполнения.
